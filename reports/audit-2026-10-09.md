# Vantage audit — onboarding + core dashboard

- **Date:** 2026-10-09
- **Scope:** Onboarding & first-run, then the core management dashboard (Overview, Monitor, Disk, Services & Ports, Network, Security). Lock down what exists; no new features.
- **Agents:** `onboarding-reviewer`, `bug-hunter`, `security-auditor`, `ui-reviewer` (read-only swarm).
- **Method:** static analysis only. No application files were modified.

Legend: **S** security, **B** bug hunter, **O** onboarding/product, **U** UI. Severity is the merged, highest-confidence rating.

---

## Verdict

The **core loop is largely sound** (Monitor, Disk, Network, Security close: discover → act → see result). The two things that most undercut the product are:

1. **First run is not honest or escapable.** The wizard cannot be dismissed and "Skip setup" does not skip (O1); ML runtimes are always reported as installed/ready even on a bare Mac (O2); a Full Disk Access prompt can fire on first load before onboarding explains it (O3).
2. **The trust boundary is softer than the README claims.** The token is disclosed by an unauthenticated endpoint and protected only by an Origin-vs-Host check that a rebinding page defeats (S1), and the Touch ID factor is enforceable at exactly one call site (S2/S3).

Everything else is medium/low and mostly correctness, state, and accessibility.

---

## Critical

### S1 — Token disclosed to a rebinding page → full remote control
- Where: `server.js` (`authorized()`), `server.js` `/api/session`, URL built from `req.headers.host`
- Vector: a page at `http://evil.example:8790` rebinds to `127.0.0.1`; `GET /api/session` (unauthenticated, origin-agnostic) returns the token; the `Origin` host equals the attacker-controlled `Host`, so `authorized()` passes for every mutation.
- Impact: complete control of all mutating routes from a remote web page; contradicts "loopback-only, cross-origin rejected".
- Fix: validate `Host` against a fixed allowlist (`localhost`, `127.0.0.1`, `[::1]`, configured `HOST`) on every request, reject `Sec-Fetch-Site: cross-site`, and stop deriving the expected origin from `req.headers.host`. Consider requiring the token for `/api/session` reads beyond first bootstrap.
- Confidence: high

## High

### S2 — Token → arbitrary code execution via `maintenance.loginItem`
- Where: `lib/maintenance.js` (`setLoginItem`), `lib/actions.js` (loginItem), `server.js` `/api/upload`
- Vector: upload an arbitrary `.plist`, then call `maintenance.loginItem` with `name: "../../…/data/uploads/<file>"`; `path.join` resolves to the uploaded plist and `launchctl bootstrap` runs it. No `danger: 'high'`, so token alone suffices; chains with S1 into remote RCE.
- Fix: reject any `name` that is not a single segment directly inside `~/Library/LaunchAgents` (assert `dirname(resolved) === LA_DIR`); stop accepting arbitrary plist uploads.
- Confidence: high

### S3 — Touch ID gate bypassed by self-enrolling a native credential
- Where: `server.js` `/api/webauthn/native/register`, `lib/webauthn.js` (`nativeRegister`)
- Vector: with the token, POST any P-256 public key to `native/register`; it is stored as an enabled credential. Then `native/options` → sign with your own key → `native/verify` → grant.
- Impact: the second factor is mintable by any token holder; there is no Touch ID ceremony to enroll.
- Fix: require a server-issued registration challenge plus an existing-credential assertion (or a one-time local bootstrap) before enrolling; never let a plain token add a credential.
- Confidence: high

### S4 — Touch ID enforced only in the HTTP action route
- Where: grant check in `server.js` `/api/actions/:id` only; `runAction` (`lib/actions.js`) has none; rules/schedule call `runAction` directly.
- Vector: `POST /api/schedule` or `POST /api/rules` with a `danger: 'high'` action; the timer fires it with no grant.
- Fix: enforce the Touch ID grant inside `runAction` (single choke point), and/or forbid `high` actions in rules/schedule.
- Confidence: high

### B1 — Unhandled stream error can crash the server
- Where: `server.js` `serveStatic` and the image/icon/gallery routes (`createReadStream(file).pipe(res)` with no `'error'` handler).
- Trigger: file removed/unreadable between `stat` and stream open.
- Impact: uncaught exception exits the process; jobs, scans and sampling die.
- Fix: `stream.pipeline(...)` or attach an `'error'` handler that destroys/ends the response.
- Confidence: high

### O1 — Wizard cannot be dismissed; "Skip setup" does not skip
- Where: `public/app.js` `[data-ob-skip]` → `onboardingNext()`; `closeOnboarding()` only reached on the final step; no close control, no Escape, no overlay click.
- Impact: a first-time user must click Continue through all 8 steps; "Skip setup" is a lie; contradicts the README.
- Fix: make **Skip setup** persist `completedAt` and call `closeOnboarding()`; add Escape/close affordances.
- Confidence: high

### O2 — ML runtimes always reported installed/ready
- Where: `lib/scanner.js` `scanRuntimes` pushes whisper.cpp/llama.cpp/MLX/ggml unconditionally (version may be `null`); `present: (d) => d.runtimes.length > 0`; `viewRuntimes` empty state unreachable.
- Impact: Setup shows a false green "ready"; the "Get set up" badge under-counts; the Runtimes page never offers install guidance.
- Fix: mark a runtime present only when its binary/version probe succeeds; let the empty state render.
- Confidence: high

### U1 — Wizard is `aria-modal` with no focus trap or background lock
- Where: `public/app.js` wizard shell; `syncScrollLock()` ignores `onboardingRoot`; `startOnboarding` never traps focus.
- Impact: Tab walks into the obscured dashboard; touch scroll moves the background; screen-reader users can operate hidden controls.
- Fix: include `onboardingRoot` in `syncScrollLock`, trap focus for the wizard's lifetime, restore focus on close.
- Confidence: high

### U2 — Monitor/Network polling destroys focus every 2–5s
- Where: `public/app.js` `loadMonitor`/`refreshProcRows` (2–3s), `loadNetwork` (5s) replace whole subtrees.
- Impact: any keyboard focus (range buttons, process Quit/Details) is lost each tick; the row cursor points at detached nodes; effectively unusable by keyboard.
- Fix: patch changed values, or skip re-render while the subtree contains `document.activeElement`; re-target the row cursor after re-render.
- Confidence: high

## Medium

### B2 — `cache.clear()` is undone by in-flight memoized work
`lib/cache.js` `memo`/`clear`, `lib/overview.js` `report`; a clear issued while `fn` runs is lost when it resolves and rewrites the entry, so post-action reclaim/health can stay stale for up to the TTL. Fix: generation/epoch guard, drop stale completions.

### B3 — Active filter wiped on every live-view poll
`applyFilter()` sets inline `display`; `loadMonitor`/`refreshProcRows`/`loadNetwork` replace the rows without re-running it, so a typed filter visually resets every 2–5s. Fix: re-apply the filter after each render.

### B4 — Metrics delta state shared between the 15s sampler and `?fresh=1`
`lib/metrics.js` `lastCpu`/`lastNet` are mutated by both; overlapping calls yield `cpu: null` and distorted net rates. Fix: single-flight mutex, or per-call baselines updated only by the sampler tick.

### B5 — `pollJob` retries forever and never resolves orphaned jobs
`public/app.js` `pollJob`: on a 404 (server restart) it retries every 2s indefinitely; the job dock stays "running" and the wake lock is held. Fix: backoff and mark failed/remove on non-transient errors.

### O3 — Overview probes Full Disk Access on load, before onboarding explains it
`lib/overview.js` `fullDiskAccess()` runs on every `report()`; `/api/overview` is uncached (ttl 0); Overview/AI News load it on first paint, which can surface the macOS TCC prompt outside the explained step (`lib/setup.js` deliberately excludes it). Fix: drop the probe from `report()` or gate it to the explicit, explained action.

### O4 — "Install helper" spins ~60s then reports success on failure
`public/app.js` permission/`[data-setup-install]` poll 40×1.5s and don't watch job status; on a Mac without Homebrew the job fails but the button still ends "success". Fix: watch the `jobId`, stop on done/failed, surface the error.

### O5 — Setup "Open" for not-installed ComfyUI/OpenClaw silently redirects to Overview
`data-goto` + `available()` gate in `setView` means the install-guidance empty states in `viewComfy`/`viewAgent` are unreachable from Setup. Fix: link to install steps inline or render the empty state instead of redirecting.

### O6 — Service health hardcodes the dashboard on port 8790
`lib/health.js` uses `http://127.0.0.1:8790/api/health`; under the documented `PORT` override it reports the dashboard as `down` and can feed a false "service down" notification. Fix: build from `HOST`/`PORT`.

### O7 — ComfyUI "Restart" targets a hardcoded launchd label
`public/app.js` always offers restart of `ai.openclaw.comfyui`; `lib/actions.js` 403s for any other install. Fix: only render when that label exists, or resolve the real label.

### O8 — Settings → General can never show Full Disk Access as granted
`/api/setup` intentionally omits `fullDiskAccess`, so the row always reads "Optional". Fix: offer the explicit Re-check on the row or persist the last probe.

### O9 — Service rows don't refresh on the action that changed them
`refreshAfterAction` for `services` only calls `loadHealth()`; the row status/buttons lag until the next full rescan. Fix: re-render the services list (or patch the row).

### U3 — Unescaped server strings in row/table HTML
Network interface rows pass `iface.*` raw through `row()`; Security/Services interpolate `port`/`pid` raw into markup and `data-*`. Fix: `esc()` consistently (or coerce numerics).

### U4 — Toggles have no accessible name
`switchRow`, settings boolean control, and wizard toggles render a checkbox with no `aria-label`/`aria-labelledby`. Fix: label the input from the row title.

### U5 — Async results and wizard step changes are not announced
Permission test results, ping/port results, scan status and "Step N of M" update elements with no `role="status"`/`aria-live`. Fix: add live-region semantics.

### U6 — Overview extras fail silently
`loadOverviewExtras` catches to `null` and blanks the health card / checklist; the disk trend shows a misleading "collecting…". Fix: error empty-state with Retry.

### U7 — Wizard has no double-submit guard; step persistence isn't serialized
`onboardingNext` is async, wired directly to click, `persistOnboarding` not awaited. Fix: guard/disable during transition and await persistence.

### U8 — Escape does not dismiss the wizard; focus not returned after close
Fix: handle Escape in the wizard's key handler and restore focus to the view on close.

## Low (batched)

- **O10** ComfyUI "Copy install command" copies a docs URL (`public/app.js`).
- **O11** "Back" doesn't persist the step, so resume jumps forward.
- **O12** Overview offers "Pull an Ollama model" when Ollama isn't installed.
- **O13** Security "How to fix" opens a generic Privacy & Security pane, not the specific one named.
- **B6** `serveStatic` prefix check lacks a path separator (`public` vs `public-secret`).
- **B7** `/api/ports/detail` doesn't range-check `port`.
- **S5** Token is persistent, not per-run, and never rotates (README says per-run).
- **S6** Non-constant-time token comparison.
- **S7** `?fresh=1` on-demand sampling is unauthenticated and can be flooded / race the sampler.
- **S8** Option injection where a host/name may start with `-` (ping/store/packages); `execFile` prevents escalation.
- **S9** Prefix path checks without `path.sep` and symlink-following on read routes (local-only).
- **S10** WebAuthn/grant hardening: signCount not checked, grants are 90s reusable bearer tokens, UV flag not required at registration, `x-forwarded-proto` trusted.
- **U9** Disk refresh error discards the whole view; no `aria-busy`.
- **U10** Context-menu click listener can be re-added after removal.
- **U11** Overlapping poll responses have no sequence guard.

## Design uplift (opinions, not bugs)

1. **Welcome step is nearly empty** — render the already-written `onboardingStackChips()` under the hero with a one-line "we already know this Mac" lede.
2. **Wizard body re-centers between steps** — top-align with a `min-height` so the header stays put.
3. **Empty states are inconsistent** — core views use bare `.empty-note`; standardize on `emptyState()`.
4. **Tables vs rows inconsistent** — pick one container per data type (tabular → table, entity → row).
5. **No value-change motion on live views** — add a short fade/count-up once values are patched, gated by reduced-motion.
6. **Monitor density is high for a 3s cadence** — collapse the six trends / explain list behind a disclosure.
7. **Wizard card language mixed** — render folder grants as `wizardInfoCard`s like other steps.
8. **Progress is a bare bar** — add `role="progressbar"` and keep the step label clear of content.

## Suggested order of work (lock down, in this order)

1. **Security floor (before anything else):** S1 → S2 → S3/S4. These are the difference between "loopback-only" being true and marketing.
2. **First-run lockdown:** O1, O2, U1, O8, O5, O4, O3, U7, U8 — the wizard must be honest, escapable, and accessible, and Setup must tell the truth about what is installed.
3. **Core-loop correctness:** B1 (crash), B4 + B2 (live/stale data), B3 + U2 (filter/focus on live views), B5, O9, O6, O13, U3 (XSS sinks).
4. **Polish:** the design-uplift list and the remaining lows.

## Coverage & caveats

- Read-only, static analysis. No runtime execution, screen reader, or contrast measurement.
- Out of scope this run: non-core views (Models, ComfyUI internals, Brew/Store, Apps, Packages, Maintenance, Agent/Activity, AI News, History, Settings), the native WKWebView bridge, PWA/service-worker, and push crypto correctness.
- Some findings are reasoning about prompt timing and stream races rather than observed failures.
